# 9SEC Evidence Workbench

**English** | [中文（繁體）](README.zh-TW.md)

**Windows rapid on-scene collection + Windows/Linux/macOS evidence analysis.** One portable Windows executable, GUI or CLI, with direct UAC evidence intake and a shared facts-based correlation pipeline. It is not a silent imaging platform or a full in-memory forensics suite.

## Download

**[Latest release (ZIP)](https://github.com/9-Security/IR_Collect/releases/latest)** — the Release provides a ZIP and matching `.zip.sha256` sidecar. Verify the ZIP, then extract and run. v0.25.1 and later use `9SEC_EvidW.exe`; the v0.25.0 archive retains the previous executable filename.

**Current published release: v0.25.2 (2026-08-17).** See
[`docs/CHANGELOG.md`](docs/CHANGELOG.md) for release details; use `-version` or `--version` and the
same-tag documentation to confirm any binary's actual capability set.

- **Runtime:** .NET Framework 4.5 or later (typical on Windows 7+).
- **GUI:** double-click `9SEC_EvidW.exe`.
- **CLI collection:** `9SEC_EvidW.exe -c [EvidenceID]` (alias `--collect`; prefer an elevated prompt for full logs, raw volumes, etc.).
- Prefer collection **output on removable media** to limit change on the examined system.

### Offline analysis & correlation (no live host, no GUI)

9SEC Evidence Workbench can also analyze artifacts **anyone** already collected — point it at a folder or evidence archive and it runs the same facts-only correlation pipeline:

- `9SEC_EvidW.exe -analyze <folder-or-archive> [out.json]` — ingest a folder or ZIP/TAR/TAR.GZ/TGZ archive; UAC output is detected, indexed, and normalized where supported → `summary_v3` JSON. Pass `-` instead of a path to read the evidence path from stdin.
- `9SEC_EvidW.exe -diff <baseline> <target> [out.json]` — compare two folders or evidence archives through their normalized facts → `diff_v1` Added/Modified/Removed JSON.
- `9SEC_EvidW.exe -correlate <out.json> <pathA> <pathB> [...]` — cross-host shared-entity + temporal correlation → `correlation_v1` JSON.
- `9SEC_EvidW.exe -graph <seedType> <seedValue> <maxDepth> <out.json> <path...>` — multi-hop investigation graph from a seed entity → `graph_v1` JSON. `maxDepth` must be a positive integer; any other value is rejected with exit code `2`.
- `9SEC_EvidW.exe -version` — tool name + version.

The GUI **Diff** tab compares the selected target with another loaded case whose Fact Store is ready.
Results can be filtered by category, change type, or source and opened in the corresponding Facts or
Timeline view. Added/Removed means observed on only one side; it does not prove presence or absence
when collection coverage differs.

Folder and archive intake keep the evidence root read-only. Canonical CSVs, rebuilt Event Log CSVs,
ShellBags output, Fact Store caches, and default CLI reports are written to a separate analysis
workspace; `analysis_workspace_v1.json` binds each generated file to its SHA-256 and the source
evidence digest. Pre-existing 9SEC canonical names inside UAC evidence remain indexed as raw input
but are not trusted in place of outputs regenerated by the current parser. Analyst workflow notes
are stored outside the evidence root under the current user's Local Application Data.

Persistent normalized Fact Store caching is optional and **off by default**. Enable it in
**Advanced -> Settings** to store a current-user cache under Local Application Data. Exact SHA-256
input matches are reported as `Reused`; changes limited to filtered Event Log CSVs are rebuilt as
`Incremental`; all other changes, incompatible metadata, or unreadable caches fall back to `Full`
with the reason shown in Summary and CLI output. The cache never replaces source evidence and may
contain sensitive normalized facts; Settings also provides **Clear persistent Fact Store cache**.

Archive intake publishes an extracted case only after a same-volume staging directory completes.
ZIP metadata is pre-scanned; ZIP/TAR intake enforces entry, single-file, total-expanded-size,
expansion-ratio, and free-space limits. Failed, cancelled, truncated, or quota-rejected imports
remove staging output instead of exposing a partial case. Generated canonical CSV, rebuilt Event Log
CSV, SQLite, workflow, manifest, and CLI JSON files are likewise written to a same-directory temporary
file and atomically published only after the writer closes successfully.

Every analysis output records the **tool version** and a **per-input SHA-256 evidence manifest** (`evidence_digest`); archive intake also records `source_evidence_sha256`. UAC account, package inventory, Apache/nginx web logs, shell-history, persistence, journal metadata/boot ranges, login history (`last`/`lastb`/`lastlog`/`utmpdump`), Linux auditd, system-text log, process, bodyfile, auth, and network sources flow into the Fact Store, while unsupported raw files remain visible as `indexed-raw`. Web-log intake supports bounded plain/gzip Common/Combined access logs and default Apache/nginx error envelopes; offset-less error timestamps remain raw, and client/proxy fields are not treated as trusted identity. Package intake supports bounded dpkg, RPM, DNF/YUM, pacman, apk, Flatpak, Snap, and macOS Homebrew command outputs; package presence is a state observation, not evidence of malicious or recent installation. Generic Linux/macOS system logs support bounded RFC 3164, RFC 5424, and ISO timestamp parsing from plain or gzip sources; yearless or offset-less timestamps retain the raw value without invented UTC. Audit records sharing one `audit(epoch:serial)` identifier are grouped without architecture-dependent syscall guessing. Login timestamps receive UTC values only when the source provides a reliable numeric offset.

UAC `hash_executables.{md5,sha1,sha256}` and `hash_running_processes.{md5,sha1,sha256}` outputs are normalized into `uac_file_hashes.csv` and untimed `UacFileHash` facts. The path/digest observations support IOC, Diff, cross-host Correlation, and Graph pivots; they do not by themselves prove execution or maliciousness.

**Try it in 5 minutes** — a synthetic two-host case ships in [`docs/sample-case/`](docs/sample-case/); the guided walkthrough [`docs/DEMO.md`](docs/DEMO.md) ([繁體中文](docs/DEMO.zh-TW.md)) runs `-analyze` / `-diff` / `-correlate` / `-graph` end-to-end (no real evidence, no elevation).

## Where it fits (early–mid incident)

Best when you need fast answers to:

- **Which hosts** might be in scope or affected.
- **Which account, process, file, or remote endpoint** deserves follow-up.
- **How lateral movement** likely progressed.
- **What was truly not observed** versus **what was never collected** (coverage vs. absence of activity).

*Assessment is grounded in this repository’s documentation and modules—not a substitute for findings from your own cases.*

## Practical value

- **Fast single-host triage on Windows:** one EXE, GUI/CLI, built for first-touch live response.
- **Cross-platform evidence analysis:** ingest UAC folders or archives from Linux/macOS systems; supported sources are normalized into the same Fact Store, Timeline, Diff, Correlation, and Graph workflows.
- **Broad collection surface:** processes, persistence, Event Logs, MFT, USN, Registry exports, browsers, Prefetch, Jump Lists, Amcache, ShimCache, SRUM—strong for suspicious execution, persistence, and user activity.
- **Not just raw drops:** facts normalization (Fact Store) so you can narrow scope with **timeline**, **entity search**, and **graph**, then return to raw artifacts to verify.
- **Lateral movement and identity abuse:** structured work around RDP, SMB, Kerberos, logons, services/tasks, and **cross-host Investigation Graph**.
- **Pivoting when logs are thin:** Jump Lists, BITS, SRUM, stored credentials, Kerberos tickets, and related artifacts still support pivoting alongside Event Logs.
- **Handoff-friendly:** Summary JSON, HTML report, and full LOG JSON for the next analyst, external tools, or reporting workflows.

## Strengths

- **Facts-only posture:** no built-in “malware” verdicts—fewer heuristic mistakes poisoning the narrative.
- **Raw + normalized together:** quick triage today, reproducible review tomorrow.
- **`collection_coverage`, parser notes, and time confidence** help separate “we didn’t see it” from “we didn’t collect it.”
- **Multi-host graph, shared entities, and timeline handoff** support sensible scoping.
- **Memory acquisition and analysis handoff** stay in the same case narrative (orchestration, sidecars, coverage)—without parsing memory images inside the tool.

## Limits

- **Still live response:** writes an output tree and leaves its own execution traces—not a zero-footprint replacement for dead-box / offline lab workflows.
- **Event Logs remain important:** cleared, disabled, or short-retention logs still blunt many storylines.
- **Memory:** external tool orchestration and validation, not embedded Volatility-class analysis—deep fileless or in-memory work still needs your specialist stack.
- **Some artifacts are first-stage parsing** (e.g. ShellBags): useful, but not full semantic recovery; see the manual and spec for known caveats.
- **Facts-only means analyst-heavy work:** great evidence packaging, not automatic attribution, prioritization, or remediation decisions.
- **Large cases:** import time, memory use, and Fact Store freshness still require operational discipline.

## Governance (v0.22+)

Separate **AI** and **Upload** endpoint allowlists; the **redaction profile** (`None` / `Basic` / `Strict`, default `Basic`) applies only to the JSON sent for **AI Analyze** (not to exported Summary files or ZIP contents). **Collection mode profile** (`Standard` / `TriageFast` / `ForensicStrict`) in **Advanced → Settings** is recorded in `collection_coverage.json`. `ForensicStrict` classifies the planned output target, requires explicit risk acknowledgement (and, by default, a second confirmation), warns strongly for system-disk output, by default skips enabled external memory acquisition/analysis handoff and blocks manual **Deep Scan** (both adjustable in Settings), always blocks post-collect ZIP upload and in-app **AI Analyze**, and records all restrictions/profile skips in coverage and analyst exports. It is still **not** a zero-footprint guarantee. Details: `docs/SECURITY.md`, `docs/USER_MANUAL.md`.

## In one sentence

If you need **fast collection, timelines, cross-source and cross-host correlation, and clean handoffs**, this tool has real operational value. If you need **silent imaging, deep memory analytics, or automated malicious verdicts**, it is not that class of product.

**Sweet spot:** Windows endpoint **initial assessment, scoping, lateral movement tracing**, and **evidence packaging before handoff**.
